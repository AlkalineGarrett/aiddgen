# /aigen-add-command

Add a custom command beyond the defaults generated by `/aigen-init`.

## References
@aigen/rules/generator.mdc

## When to Use

`/aigen-init` generates common commands (/plan, /task, /review, /commit, /explain, /debug, etc.). Use `/aigen-add-command` when you need something specific to your workflow that isn't covered.

## Approach

Single question, then confirm:

1. Ask what the command should do
2. Infer name, behavior, and guardrails
3. Show what will be generated
4. Generate on confirmation

## Behavior

### Step 1: Ask

```
What do you want the AI to help with that isn't covered by existing commands?

Existing: /plan, /task, /review, /commit, /explain, /debug, [others from init]
```

### Step 2: Infer and Confirm

Based on description, infer:
- Command name (verb-based, short)
- What the AI should do
- Which existing rules apply
- Appropriate guardrails

```
I'll create: /[name]

Behavior:
1. [inferred step]
2. [inferred step]
...

References your: core.mdc, [other relevant rules]
Guardrails: [inferred]

Create this? Or tell me what to adjust.
```

### Step 3: Generate

Create command file and update help.md.

## Examples of Custom Commands

| User says | Creates |
|-----------|---------|
| "help me write API documentation" | /api-docs - analyze endpoints, generate OpenAPI or markdown |
| "analyze test coverage gaps" | /coverage - identify untested code paths, suggest tests |
| "help migrate from X to Y" | /migrate - plan migration steps, track progress |
| "generate mock data for testing" | /mock-data - create realistic test fixtures |
| "help write release notes" | /release-notes - summarize changes since last release |
| "audit dependencies for issues" | /audit-deps - check for vulnerabilities, outdated packages |
| "help with database schema changes" | /schema - plan migrations, generate SQL |

## Output Generation

Generate [output]/commands/[name].md:

```markdown
# /[name]

[Description based on purpose]

## References
@rules/core.mdc
@rules/stack/[relevant].mdc
[other referenced rules]

## Usage
/[name] [options] [arguments]

## Behavior

[Steps the AI should follow, derived from scope]

1. [First step]
2. [Second step]
...

## Constraints

[Derived from guardrails and core.mdc]
- [Approval requirements]
- [Inherited from core.mdc]
```

Update [output]/commands/help.md to include the new command.

## If User Is Unsure What to Add

Reference the "Included based on context" table in init.md - these are commands that may not have been generated based on the user's lifecycle/team/risk choices, but could be added manually.

If none of those fit, ask user to describe their workflow need and create a custom command.
